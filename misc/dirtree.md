# Directory tree structure

An organised work directory simplifies the accessibility to data.<br />

```{bash}
.
├── seq
├── rep
├── cps
├── scr
├── map
├── plots
└── runner.sh
```
The *seq* dir stores paired-end illumina <code>fastq</code> files of the samples to process. The <code>fastq</code> files **must** be named: <code>samplename.R1.fastq.gz</code> and <code>samplename.R2.fastq.gz</code>. The *rep* dir stores the reference ```saccharomyces_all_assemblies.fa``` genome, a concatenation of eight *de novo* genome assemblies, one for each *Saccharomyces* species today known. At the end of the run, *cps* (which stands for *checkpoints*) hosts two *txt* files: <code>BWA.cps.txt</code> and <code>COV.cps.txt</code>. The name of the samples will be printed inside these two files at the end of <code>STEP1</code> and <code>STEP3</code>, respectivelly. The samples, which names are stored inside these files, will not reanalysed a second time. This allow the user to:
- rerun specifc sample, 
- restart the run in case the pipeline ends with errors, 
- add a new batch of samples inside *seq* and run the pipeline.

The *scr* dir contains the scripts that make the pipeline work. The *map* and *plots* directories are generated by the pipeline. Although coding purists disagree, the position of the runner outside *scr* is a pragmatic choice. The <code>runner.sh</code> is the only file you will have to interact with and you may need to do it frequently so, it is placed at the level of the working directory.
